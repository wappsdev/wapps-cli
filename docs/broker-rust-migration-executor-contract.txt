2. Proposed local input/manifest contract
----------------------------------------
Local validate/plan must work without loading broker credentials, claiming a lease,
starting a daemon or contacting any service. Real inputs are supplied by an authorized
operator, never discovered from installed plugin paths. The executor does not create,
copy, checkpoint, repair or upgrade a live database. Backup acquisition is outside it.

Mapping input: retain the strict curated {sources:[...]} shape, exactly six fields
per source: project, snapshot (absolute path), source_mission_id, target_mission_id,
selected_question_ids, approved_lossy_transformations. One to four distinct allowed
projects; distinct targets; mission IDs match [a-z0-9][a-z0-9._-]{0,127}. Duplicate
JSON keys and unknown fields refuse. Expected principal/destination/runtime approvals
belong to execution bindings, not source-data mapping or operation key material.
Bind mapping_sha256 to the EXACT mapping-file bytes, not reparsed/rounded JSON.
Whitespace/path/approval edits require new offline review and cannot resume an attempt.

Snapshot input: existing immutable, consistent, standalone SQLite file from stopped
writers; private UID-owned regular file, single link, no symlink path components,
private source containment; reject -wal, -shm and -journal sidecars. Open an escaped
file URI with mode=ro&immutable=1 and explicit READ_ONLY without CREATE; query_only=ON,
trusted_schema=OFF. Check schema tables, required columns, mission uniqueness/state;
read a transaction and hash file bytes before/after with ring SHA-256. Recheck identity
and sidecars. Immutable assumes stable bytes; it does not freeze concurrent writers.
Before/after hash alone cannot establish consistency. Never retry a changing source.
Only missions (id/status), work_items and work_questions are interpreted. No queries
of jobs, transcripts, leases or credentials; file hashing covers opaque file bytes.

Preserve original column names/selected rows as typed SQLite values. Integer values
must remain i64, never f64 or JS Number. Finite REAL archive values must retain their
exact binary64 bit representation in the production archive (tag real_bits_hex);
this avoids inventing cross-language decimal equivalence. Null/text/integer retain
native JSON null/string/integer values. BLOB, invalid Unicode and non-finite REAL
are invalid inputs, not base64 export or silent conversion. Unknown non-null source
columns block as the oracle does; list them in diagnostics, not executable payloads.
No timestamp/position coercion: integer SQLite storage is required where the oracle
requires int. The tagged REAL archive is a proposed production-format distinction;
never reinterpret or rewrite the frozen Python JSON to match it.

Proposed new manifest format: wapps-broker-replay-plan-v1, not the Python fake format.
Required top-level fields:
  format, status (blocked | ready_for_review), nothing_migrated:true,
  live_replay_safe:false, mapping_sha256, selected_scope, projects_not_provided,
  excluded_project:"wapps-platform", issues, projects, limits, live_prerequisites.
Project fields retain the six source mapping fields plus snapshot_sha256,
source_items, source_questions, counts, unsupported_metadata, transformations,
batches and questions, as in the curated planner. Batches retain depth, source_ids,
items:{source_id,parent_source_id,body}, reserved_body_bytes. Questions retain
source_id, work_item_source_id, body. body carries only title/intent/optional horizon
or question/optional proposal; source references are not destination IDs.

Graph/state rules: duplicate IDs never overwrite; reject missing, closed and
cross-mission parents, cycles, child horizons and unknown states. Root horizon may
be absent/null in the source or now/next/later/someday. Iterative topological levels,
ordered by (original i64 position, source ID), earlier-depth parents only; split at
500 items or conservative body budget, never combine parent/child in one batch.
Question state/selection rules are unchanged. Retain open unselected question rows
in a BLOCKED manifest; do not silently discard them. Oversize, blank and padded
required text blocks; omit optional wire fields rather than sending explicit null.

Manifest_sha256 is SHA-256 of the EXACT published manifest bytes, including the
single trailing LF. Publish a new private 0600 file exclusively, file and directory
sync; never stdout/overwrite/force. Fixed diagnostic codes only, no source text,
paths or raw exceptions. Exit 0 means ready for OFFLINE review, 3 written blocked
manifest, 2 invalid/unsafe input or I/O failure. These exits do not mean migration.
Missing required sources and a blocked/partial manifest cannot authorize full replay.

3. Stable operation identity and four distinct fingerprints
-----------------------------------------------------------
Allocate the entire ordered operation/key list before any creation send. Allocate
keys and source identities, NOT destination IDs (the server mints those). Bind the
immutable manifest, mapping, principal, destination and partition separately.

Client operationKey stays exactly the frozen od10k1- contract:
  od10k1- + lowercase SHA-256(compact sorted-key ASCII JSON of
  {version:1,project,source_mission_id,target_mission_id,kind,source_ids}).
kind is work_add or work_ask. source_ids is an ORDERED list. No whitespace; Python
ensure_ascii=True escaping, lowercase hex and UTF-16 surrogate pairs for non-BMP
scalar values. Escape U+007F too (Python does); reject unpaired surrogates. The
fixed key is 71 ASCII characters; platform grammar is case-sensitive/untrimmed,
1–128 ASCII characters, first alphanumeric, remainder alphanumeric or . _ : -.

Content/title, snapshot digest, principal, returned IDs, lease capability/fence,
clock and transport request ID are not in this key. Changing them cannot mint a
replacement recovery identity. Principal is separately server-scoped and journal
bound. Changing project/source/target/verb/order/partition changes key material but
is FORBIDDEN after an attempted send, not a recovery technique. Original batches
stay immutable even if a future transport could fit a different partition.

Distinct digests; never substitute one for another:
  snapshot_sha256: original opaque SQLite file bytes.
  mapping_sha256 / manifest_sha256: exact immutable private file bytes.
  request_sha256: exact stored authority-free resolved creation JSON bytes.
  semantic_sha256: normalized typed server semantic JSON UTF-8 bytes.
Journal integrity sha256 additionally covers exact journal document bytes, not keys.
Checksums detect corruption; none proves origin, consent or rollback resistance.

Server semantic: work_add hashes a Vec<NewWorkItem> in declaration field order
(title,intent,parentId,horizon,discoveredFrom), absent optionals serialized null.
work_ask hashes the tuple [workItemId,question,proposal], absent proposal null.
Normalized ECMAScript trim and UTF-16 bounds apply first. Wire explicit null/unknown
fields refuse; empty trimmed proposal refuses. Object input order/escape spelling
is immaterial; array order matters. The server's typed hash excludes key/principal/
authority/time but authorization does not. Not Python sorted ASCII JSON, not GoEscape,
not JSON.stringify(input), not serde_json::Value map ordering.

Serialization prerequisites grounded in source/types and synthetic measurement:
- Python integers and Rust i64 preserve 9007199254740993; JS JSON.parse/stringify
  yields 9007199254740992. Source position/timestamps must not pass through JS or f64.
  Text-only key identity uses integer version 1, so avoid adding numeric source rows
  to the key. Authority fencingToken must be an integral 1..=9007199254740991 value;
  reject bool/fraction/nonfinite/out-of-range, do not round it.
- Python ensure_ascii escapes DEL, é, U+2028 and emoji; serde_json default emits
  valid UTF-8 fragments. Existing gojson::GoEscape additionally escapes <>& and
  U+2028/U+2029, which neither server typed hash nor Python key encoding wants.
  Use serde_json::Serializer with a narrow ASCII string Formatter for key identity,
  sorted fixed identity fields; do not implement a general JSON library or use
  gojson for fingerprints. Formatter::write_string_fragment/write_char_escape are
  already available in the project's dependency. Version is explicitly integer.
- No NFC/NFD normalization. Rust str::trim is wrong: BOM is ECMAScript whitespace,
  NEL is not. Preserve those distinctions; count encode_utf16(), not bytes/chars.
  Shorten only at whole Unicode-scalar boundaries within 500 UTF-16 units.
- serde_json raw_value/float_roundtrip features are already enabled. They do not
  provide Python ASCII output, JS number parity, duplicate-key rejection or exact
  arbitrary SQLite-value semantics. Use a duplicate-checking serde visitor, not
  Value's last-key-wins parser, for mapping/manifest/journal inputs.

Final-envelope sizing: preparation's 1,048,576 budget/4,096 reserve is conservative,

4. Smallest proposed Rust interface (declarations, not implementation)
--------------------------------------------------------------------
One broker::replay module in the CLI product; no new shared package or provider
executor abstraction. Reuse existing daemon/forwarding, not owner::http. Private
constructors keep validated inputs from being fabricated through ordinary callers.

Interface declarations below are proposed Rust signatures; bodies do not exist:
  fn validate(mapping: &MappingInput, sources: &[SnapshotRows])
      -> Result<Manifest, StopCode>;
  fn allocate(manifest: &ValidatedManifest, binding: ExecutionBinding)
      -> Result<Allocation, StopCode>;
  fn execute(plan: &Allocation, journal: &mut Journal, backend: &mut dyn ReplayBackend,
      action: ReplayAction) -> Result<RunReport, StopCode>;
  fn verify(plan: &Allocation, journal: &Journal, destination: &DestinationInventory)
      -> Result<VerificationReport, StopCode>;

MappingInput = parsed strict mapping plus exact input-byte digest.
SnapshotRows = project/source identity, file digest, typed mission/item/question
rows from the supplied read-only adapter; in-memory curated fixtures supply the
same shape without SQLite. Manifest is blocked or ready_for_review, not authority.
ValidatedManifest = ready manifest with original byte/mapping/snapshot digests and
all graph/scope/text checks passed; private constructor, no fake-manifest importer.
ExecutionBinding = exact expected principal, destination origin/mission bindings,
reviewed source mapping identity and approved retained-history evidence reference.
It contains no credential. Allocation = complete immutable ordered operations,
source reference graph, keys and digests; no resolved child destination IDs yet.
ReplayAction = Start | ResumeSameKeys; supplied by the approved operator entrypoint,
not inferred from file presence/checksum or approved_lossy_transformations strings.
Journal = private locked durable file plus validated state; not a public JSON Value.
StopCode = fixed enum codes for scope/source/schema/authority/size/protocol/conflict/
uncertainty/drift/durability; no raw text, paths or underlying error formatting.
RunReport = per-operation acknowledged counts/IDs references, current stop location,
unknown operation count, pending count, verification and lease disposition; private
IDs/fields remain private. Console output only fixed codes/counts.
VerificationReport = exact retained-field/link comparison and drift codes, not an
ability to repair or undo. DestinationInventory = all safely read work rows and
nested open questions plus reviewed pre-existing target baseline; no job result reads.

ReplayBackend has only these operations (proposed method signatures):
  fn claim(&mut self, target: &TargetBinding) -> Result<LiveLease, CallFailure>;
  fn create(&mut self, op: &ResolvedOperation, lease: &LiveLease)
      -> Result<CreationReceipt, CallFailure>;
  fn inventory(&mut self, target: &TargetBinding)
      -> Result<DestinationInventory, CallFailure>;
  fn release(&mut self, target: &TargetBinding, lease: &LiveLease)
      -> Result<(), CallFailure>;
TargetBinding = exact mission/origin/expected principal and verified schema/limit
binding. LiveLease = in-memory capability, integral fencing token, heartbeat deadline
and validated owner/provider/mission binding. ResolvedOperation = fixed verb/key,
ordered source IDs, exact authority-free payload bytes and digests. CreationReceipt
= ordered validated workItemIds or one validated questionId, matching operation.
CallFailure = KnownUnsent | AuthoritativeRefusal | OutcomeUnknown, with fixed code.
No arbitrary tool name/URL, owner mutation, grant operation, agent dispatch/report,
job-result discharge, force release or identity-switch method is provided.

Claim status may be read through the existing orchestrator_status path within the
backend; implementation must verify held state, owner.id==expected principal and
matching fencingToken/mission against the just-returned claim authority. Claim's
response itself contains authority/deadline, NOT the principal. Route-list health
or an asserted local principal is not evidence. Test the claim+status binding and
unchanged auth channel; stop before creations if it cannot establish identity.
Claim provider is the already selected orchestrator declaration, not selection of
an LLM/model, launching a worker or a new execution-context design here.

6. Proposed journal, uncertainty, crash boundaries and accounting
----------------------------------------------------------------
New format only: wapps-broker-replay-journal-v1. Refuse all legacy/fake formats,
unknown keys/states, duplicate keys, corrupt/partial bytes and missing resume files.
Integrity envelope {journal:<document>,sha256:<hex>} uses a defined compact UTF-8
serialization of journal, fixed struct order, exact integer/string types; no JS
round trip. Store/compare prior complete file bytes while holding persistent lock.

Journal document fields:
  format, manifest_sha256, mapping_sha256, principal, destination_bindings,
  allocation_sha256, entries, verification_state, lease_disposition.
Each entry fields:
  operation_key, kind, project, source_mission_id, target_mission_id, snapshot_sha256,
  source_ids, state, request (absent until resolved), request_sha256,
  semantic_sha256, destination_ids, reason.
The request value is exact authority-free payload JSON (no routing key/authority);
its serialized bytes are the request digest input. allocation_sha256 binds all
ordered immutable entry identities/partitions. Every binding and original source
row/selection/transform remains locked by manifest/mapping digests. Do not persist
Access tokens, service credentials, capabilities, full frames or headers. Integer
fence may be checked in memory; it is not journal identity or recovery permission.
Mappings are derived from ordered acknowledged entries, not a second mutable map.
Mapping scope includes project/source/target/snapshot/source ID; duplicate titles
and reused IDs in other projects never establish a match.

States: pending, in_flight, acknowledged, unresolved. Keep Python keyed semantics:
known local pre-send errors leave pending and send nothing; authoritative refusal
for an attempted operation stops without pretending that earlier uncertainty was
rolled back. No need for a second general retry state machine. Refusal reason is a
fixed code; preserve an already acknowledged entry/IDs on a current replay refusal.

Normal transitions:
  validated allocation -> durably publish all pending entries -> resolve next body
  -> check exact frame size/current binding -> durably publish in_flight+request
  -> one admitted keyed call -> validate full result/cardinality/order/uniqueness
  -> durably publish acknowledged+ordered IDs -> only then advance successor.
Uncertain/malformed response -> unresolved -> stop ALL later operations/projects.
A crash leaving in_flight is uncertainty even if no socket bytes were sent. An
unapproved resume may validate locally but emits ZERO cloud mutation calls, including
claim, acknowledged-key replay and release. A separately authorized resume validates
all immutable history first, re-establishes same-principal current authority and
uses exact stored keys/payloads. New valid lease is permitted; stale/revoked/wrong
capability never bypasses current admission. Confirm every acknowledged original
ordered result before dependent work; keep original IDs if current replay is refused.

CreationReceipt validation: correct JSON-RPC version/correlation ID, exactly result
OR error, valid MCP content/isError/structuredContent shape, non-refusal creation
payload, expected ID field/count, nonempty bounded IDs, no duplicates within/across
same-mission verb results, expected ordered original IDs on acknowledged replay.
Do not promote arbitrary extension fields into envelope status. Successful content
with invalid IDs is uncertainty, not a zero-commit proof. Do not repair by sorting.

Crash/durability boundaries and permitted next action:
  Initial allocation or intent file/file-sync/dir-sync fails: zero sends; stop.
  Intent committed, process exits before send: in_flight; approved same-key recovery.
  Send starts, response lost/parse failure/cancelled: unresolved; no automatic retry.
  Server SQL rolls back with authoritative refusal: no current batch partial commit;
    still stop; previously committed operations remain recorded.
  Server commits, response/alarm fails: unknown locally until authorized same-key result.
  Ack validation succeeds but local publication fails: stop before dependents; restart
    sees old in_flight OR full acknowledged file, never infer success from memory.
  Ack file published, process exits: reopen, validate, recheck current authority/results.
  Directory sync fails AFTER replacement: new bytes may be visible but durability is
    not proven; stop without issuing successor or assuming old/new document selection.

Filesystem mechanics: UID-owned 0700 containment directory; walk/open with dirfds
and no-follow, files 0600 regular/single-link; persistent lock inode with exclusive
nonblocking flock; exclusive sibling temp, complete write, file sync, first
publication without overwriting any existing name, then directory sync; subsequent
atomic replacement only after checking exact prior bytes. Never chmod an untrusted
existing directory to make it acceptable. Retain orphan crash files; no temp/lock
sweep, repair, force or truncation. Advisory locking/checksums do not defend against
coherent same-UID tampering/rollback, hostile writers or hardware power loss.

Existing rustix fs/process features expose openat/linkat/renameat/flock/fsync. Existing
atomicfile::write syncs file then rename but lacks directory fsync, prior-byte checks,
persistent writer lock and exclusive first publication; do not falsely reuse it as
sufficient journal durability or broaden that shipped helper in this lane.

Per-operation accounting: no global transaction across batches/missions. Report
acknowledged item/question counts by operation/project separately from unresolved
attempt counts and pending counts. Example curated trace: 2 roots acknowledged,
child acknowledged, question response lost => 3 known created items, 1 UNKNOWN
question operation, not "0 migrated" or "complete". Source archive/config rollback
cannot undo these creations. Question recovery uses its own key and receipt; no
second question. No compensating closes, deletes, title adoption or inventory
absence inference. Final verification compares exact retained fields/links and the
reviewed pre-existing target baseline, not only aggregate count. Receipt after
closure/withdrawal still proves creation, not correct current final content.

Lease release is a separate admitted operation and outcome. Stop means no later
creation, not concealed successful release. Report held/released/unknown/refused
lease status and required reconciliation; no takeover or forced release. A cut-over
must not restart old writers after ambiguous/committed operations on the theory
that restoring local configuration rolled back cloud data. Retirement stays 13.12.

7. Exact remaining engineering gaps / gates
