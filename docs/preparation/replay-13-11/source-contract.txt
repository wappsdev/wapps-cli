Recorded contract
-----------------
Only work_add/work_ask accept optional operationKey: case-sensitive, untrimmed
ASCII, 1-128 characters, first alphanumeric, remainder alphanumeric or . _ : -.
Unknown fields and null optionals refuse. Principal comes from authenticated
routing, not body data. Claim admission and current live capability/lease apply.

Semantic hash: SHA-256 of normalized typed serde JSON, UTF-8 and compact.
work_add hashes ordered NewWorkItem vector: title,intent,parentId,horizon,
discoveredFrom in that field order, absent optional fields serialized null.
work_ask hashes [workItemId,question,proposal], absent proposal null. ECMAScript
trim and UTF-16 bounds apply before hashing; empty trimmed proposal refuses.
Input object order/escaping are immaterial; array order matters. Key/principal/
capability/fence/time are excluded from semantic hash, not from authorization.

Receipt scope is mission-local database + (principal,fixed verb,key).
Current lease is rechecked BEFORE receipt lookup. Matching fingerprint returns
original result and touches current lease without rechecking mutable creation
preconditions. Conflicts refuse. Unreadable committed results fail closed.
Mutation/receipt insertion/touch occur in one synchronous transaction: no upsert,
no partial mutation on SQL/insert/touch error. Post-commit response/alarm failure
can lose acknowledgment without undoing commit.

Receipt lifetime is mission lifetime: no expiry/eviction/pending facility or
result lookup endpoint. Both first and replay success are 201 with workItemIds
or questionId; no replay marker. Conflict is 409 OPERATION_KEY_CONFLICT,
details.refusal operation_key_conflict, retryable false, no Retry-After.
Different principal/mission/verb means independent creation, NOT recovery.
