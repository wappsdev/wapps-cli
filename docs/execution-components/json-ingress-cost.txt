Workload selection (all synthetic; no user/provider/store data)
--------------------------------------------------------------
Light response: valid MCP/JSON-RPC envelope, one fractional priority and two
integers, mostly strings/booleans. Time from_str::<Value>, as in forward.rs:219,
and from_slice::<Value>, as in daemon/mod.rs:159 and broker/mod.rs:164. These
are the actual serde ingress stages, NOT full HTTP/framing/validation/redaction.
Enrollment: version 1 and three synthetic roots, one integer, no floats. Use
serde from_slice with the exact Enrollment/Project schema from config.rs.
Those private types are mirrored in the harness; Config::load, filesystem
validation, credential loading and DNS are deliberately NOT called.
Quota token: Value ingress plus actual read_quota; primary/secondary fields,
four fractional and two integer tokens. Quota rate: same pure path, utilization
and reset, two fractional tokens. These ordinary finite fractions are binary
exact (e.g. .125/.375/.90625); they do not exercise all lexical slow paths.
Heavy response: valid structuredContent extension with 128 synthetic samples,
384 fractional and 258 integer tokens; 13,605 bytes versus the bridge's 4 MiB
response bound. Simple fractions, not a claimed production payload distribution.
Raw archive: actual wapps::execverb::exec_env_and_values, synthetic envelope
only; 257 fractional lexemes stay raw, including whitespace. No process runs.
This covers an existing raw_value consumer, not materialized float conversion.

After retaining all initial results, add two long-decimal cases rather than
concluding from binary-exact fractions alone. Quota precision uses the frozen
997473240364.3429 reset plus a long utilization percentage. Precision-heavy
response has 128 repeated synthetic telemetry tuples, 384 fractional tokens
with 16-17 significant digits and 258 integer tokens, 16,830 bytes. Both use
the same accepted serde/pure-quota stages. The repeated tuples are a bounded
illustrative workload, NOT real traffic or a representative provider corpus.
